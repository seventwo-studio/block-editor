# Current writing measurements

`benchmarks/workloads-writing.json` runs the same preserved-content editing and offline-history workloads through explicitly selected protocols4,5 and6. Each protocol has32,128,512 and2,048 edits per author, one excluded warmup and three repetitions. The CI smoke runs all three ordinary cases with eight edits per author, one repetition and no warmup. Smoke verifies the measurement harness; it does not accept release limits.

Use `PERFORMANCE_WRITING=true` with the native runner or browser performance suite. The native runner also requires `PERFORMANCE_BINARY_CONFIGURATION=release` (or `debug` for explicitly qualified screening). Android's existing performance instrumentation accepts `performanceWriting=true`; the runtime runner executes legacy and writing measurements separately. Reports are named `performance-writing-<runtime>.json`. The parity verifier requires all seven current writing reports with the same source and expected tree, workload hash, exact runtime-provenance artifact hashes/sizes, cases, final documents, retained history and receipts; legacy reports remain separate. Protocol and epoch assertions prevent silently measuring an older engine.

Native timing includes JSON, pipes and a fresh `/usr/bin/time -l` child. Its peak RSS covers that child across workloads; disk caches remain uncontrolled. Browser reports separate compile, instance and first-session phases and track allocated WASM linear address space, which excludes resident pages and JavaScript/browser heap. Android reports selected packaged JNI hashes and sampled whole-process PSS after create/receive/save/restore; this is not continuous peak or rendered app memory. Sampling occurs outside individual call timers. Rendering, network, assets and physical-device interaction are outside these measurements.

Numeric budgets remain unagreed in ST94. Preserve the completed earlier screening and the incomplete earlier report under their own source/artifact identities. Qualify full repeated release measurements before proposing limits or accepting ST39; passing smoke or emulator timing does not establish physical minimum-device budgets.
