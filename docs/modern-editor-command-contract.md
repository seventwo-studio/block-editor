# Modern editor commands and interaction states

Planning contract for [ST-120](https://linear.app/seventwo/issue/ST-120), reviewed 5 October 2026. Apply the [compatibility and migration boundary](modern-editor-compatibility.md), [visual reference](modern-editor-visual-contract.md) and [reuse/scope map](modern-editor-reuse-and-sizing.md). Core semantics remain shared Swift; native adapters and the later WASM facade call that core rather than implementing competing document models.

This specifies the intended command outcomes and reviewed local/collaborative scenarios. Existing behaviors have source and selected runtime evidence; new title/appearance/column/protocol behavior remains an implementation requirement for ST-122 and independent accepted fixtures for ST-140. Planning completion never substitutes for those runtime passes.

## Reuse and wire boundary

`WritingSession.swift` currently accepts protocols 3–6, defaults to 3, and exposes atom-anchored `WritingPosition`, `WritingSelection`, rich clipboard, structural origin IDs, schema conversion and author-local history. `Structure.swift` recognizes block/item/row/cell collections; columns and document metadata are absent. Apple `WritingEditorModel` commits native input, captures origins before held peers drain and resolves the target again. Compose's `WritingSession.kt` and TypeScript's `src/swift.ts` explicitly select the supported versions. Preserve these older entry points and histories.

Reserve **collaboration protocol 7** for the modern representation; current protocol-7 tests assert rejection by old implementations, not existing modern support. Do not add modern fields to a protocol-3–6 baseline and hope old peers preserve them. Explicit new bridge entry points `createModern`, `restoreModern`, `cutoverToModern`, `modernDocument` and `modernCommand` prevent accidental promotion of legacy `create`/`restore`. Swift/JNI/WASM must agree on protocol/format admission and command errors; expose a capability query before enabling modern controls. ST-122 implements these reservations and updates the negative-version tests without weakening old-client rejection.

The modern document discriminator is `format: "seventwo.block-editor.document"`, with independent integer `formatVersion: 1`. Its exact semantic fields are `documentID`, plain `title`, `appearance` and ordered `blocks`. `appearance` is `{fontFamily: "sans" | "serif" | "monospace", fontSize: "small" | "default" | "large", pageWidth: "readable" | "wide"}`. Defaults are empty title and sans/default/readable. The 680/720/760 and 16/17 visual-study choices are comparison settings, not extra persisted presets. Canonical serialization uses deterministic key ordering and preserves admitted unknown fields. Reject conflicting envelope/session document identities before changing state.

Title is a shared text field rooted in a document origin, conceptually `WritingField(node: .document(documentID), name: "title")`. Add an explicit document-origin discriminant rather than a fake visible block or reserved user block ID. Positions still carry document and epoch. Title admits scalar-safe plain text only; headings/body are not consumed to infer it. Enter in the title settles composition and moves to the first body insertion position without adding a newline or consuming a heading. Title is a separate text-selection surface; body multi-block actions do not select or delete document metadata. External multiline title paste explicitly normalizes line breaks to spaces; direct newline title mutations reject unchanged. Appearance fields are independent shared scalar registers; changing font size must not overwrite a concurrent page-width change. Semantic text ink/fill use versioned marks `{type: "semantic-color" | "semantic-background", value: <palette-name>}`; block defaults use scalars `semanticColor` / `semanticBackground`, overridden by explicit inline roles. Palette names are `neutral`, `green`, `blue`, `purple`, `amber`, `red`; absence means default. These new fields/mark kinds require protocol-7 validation; old validators currently admit only bold/italic/strikethrough/code/link marks. Preserve existing unknown block fields and the original representation of unadmittable inline data via the compatibility archive/read-only path.

The modern layout tag is `type: "columns"`, with `id`, exactly two ordered `columns` objects `{id, children: [...]}` and integer `splitBasisPoints`. Add a column-container origin/kind and typed `children` collections, never indexed-array replacement. The default split is 5000; valid author input is 1000–9000 inclusive. A layout's column identities/order cannot be individually inserted, removed or swapped through generic setters. The visual reference samples 30/50/70 percent; it does not prescribe these as the entire valid wire range. Before activation, detect legacy opaque fields/types colliding with newly reserved meanings; refuse reinterpretation and retain the original archive/read-only document until a lossless preservation mapping is reviewed. Never guess that a previously opaque legacy `columns` payload is a new layout.

The whole session baseline, batch, receipt and saved history use protocol 7 and the same document identity/epoch. Format revision and protocol version are checked independently. Unsupported format/protocol/epoch, mismatched baseline, conflicting duplicate change IDs and resource exhaustion reject before acknowledgment/publication. Existing fresh-epoch archive/reconciliation requirements apply; no old operation, receipt, text anchor or Undo stack is reused across cutover. Do not tighten existing valid-document limits to the old TypeScript facade's smaller limit. Bound and account separately for accepted history, held remote packets and pending recovery.

## State and command boundary

Selection has one of: no document target, caret, text range (possibly multiple fields), whole-block selection, or mixed multi-block range. Text endpoints are atom/origin anchored with affinity and UTF-16 scalar-safe offsets at adapter boundaries. A range may visually span an atomic reference label, but mutation cannot split that reference. Preserve backward/forward direction in adapter state even when a normalized mutation range has the same endpoints. Whole-node selections are origin IDs in logical document order; reject ancestor/descendant overlap, duplicate nodes and incompatible collection kinds.

Composition, focus and menus are orthogonal local states, not extra document blocks. A menu records its command target, saved anchored selection, originating input, pre-menu focus and an invocation generation. An asynchronous action records the same target plus a cancellable request identity. A drag records original shared split/placements and a local preview. These records are scoped to document/epoch and never synchronized as content.

| Event | Required transition / content boundary |
| --- | --- |
| Open contextual menu | Capture origin and anchored selection; keep content unchanged. On touch retain the selection while native input focus is transferred to the tool |
| Select a command | Validate target/policy before ending composition; commit native draft once, drain held peers safely, then re-resolve target/selection and availability. Execute atomically only if still valid |
| Dismiss menu / Escape | Discard menu drafts/previews, resolve the saved selection and restore its input if live; no Undo entry. Never refocus after the user has deliberately focused another document/control |
| Begin/update IME marked text | Hold remote materialization for the composing input; keep marked draft local. Do not turn provisional characters into repeated author transactions |
| Commit IME / host command | Commit the scalar-safe final draft once, release the remote hold, then resolve anchors. A commit failure retains draft and accepted content; the command does not run |
| Cancel native composition | Use the platform's composition cancellation result; retain accepted shared text, then release held peers. Do not invent text by trimming the marked range |
| Focus elsewhere / app background | Settle or explicitly preserve native draft using the host lifecycle. Save accepted state, pending recovery and held/unacknowledged packets separately; loss of view focus is not permission to discard text |
| Receive peer changes | Preserve anchored selection through moves/conversion; refresh projection without rebuilding the active input by display label. Deleted target uses the fallback below; pending merge recovery remains visible |
| Async completion / paste provider | Recheck document/epoch, request generation, liveness and policy. Apply at the captured target if valid; otherwise retain the result for explicit retry/copy or cancel. Never insert at whatever caret is now active |
| Switch stacking / text scale | Remeasure presentation only. Preserve logical selection, shared split, Undo and document order |

Focus fallback after destructive edits resolves the command's returned position first, then nearest surviving text at the former boundary (following sibling, preceding sibling, then editable document surface/title). An empty body exposes an insertion position without persisting a placeholder until the first author edit. A deliberately deleted block's descendants are deleted; unrelated peer text in surviving blocks is preserved. Remote deletion of a composing target must not silently retarget the draft to another block with the same label: retain/export the draft and offer recovery. Programmatic refresh cannot steal user focus or reopen a dismissed menu. ST-121 validates these working transitions.

Slash insertion captures the query's atom range and menu choice. Typing filters without rewriting unrelated content; arrows select, Return atomically consumes only the captured slash-query atoms and performs the selected insertion/conversion, and Escape closes the picker while retaining typed query text and the caret. The touch picker uses the same catalog and insertion semantics without inventing a slash query. Queries that become stale after peer edits are re-resolved or cancelled explicitly; no whole-paragraph replacement to remove a query.

Every mutation uses a checked request `{documentID, epoch, command, target, arguments}`. The result is a materialized document plus anchored selection/focus intent and the actual admitted author transaction ID, or an explicit unchanged/no-op/error result. Hosts may attach local invocation generations; wall time and local pixel geometry do not decide replicated order. The engine rechecks structure and policy after composition/remote drain. Failed availability, validation or atomic projection leaves accepted document and history unchanged. Recovery-required is distinct: retain the complete rejected union separately, keep the last accepted state and disable further conflicting author edits until explicit repair. Do not report a recovered merge as a successful ordinary command.

For the new bridge, the outer command is `modernCommand` and the checked object is `request`. Its command discriminants are `replaceText`, `insertBlock`, `splitBlock`, `mergeBlocks`, `softBreak`, `convertBlock`, `format`, `listStructure`, `move`, `duplicate`, `delete`, `setLink`, `paste`, `undo`, `redo`, `replaceTitle`, `setAppearance`, `setSemanticColor`, `completeAsyncBlock`, `createColumns`, `removeColumns`, `resizeColumns`. Existing shared target/position/selection types gain the explicit document/column origins above. Core copy has a separate read-only `modernCopy` operation returning the versioned clipboard; cut composes successful host clipboard publication with shared `delete`. Toggle disclosure, menu/typing-style drafts, local resize previews and outline/focus mode are adapter actions without wire mutations. The response distinguishes `applied`, `noop`, `unavailable` and `recoveryRequired`; transport/runtime exceptions retain the existing structured error boundary. Selection/focus intent is local command-result data, not a broadcast instruction to move peers' focus.

Availability combines shared validity with local host authoring policy. Reduced hosts do not acquire full insertion/conversion/column-resize tools. Preserve their richer accepted content through text/checklist/reorder. Existing list-item indent/outdent remains confined to list hierarchy; no general document-block indentation or arbitrary parent/child creation is exposed. A local creation restriction does not strip accepted remote content.

## Command outcomes

`One` below means one atomic author transaction and one Undo step for that deliberate action. Typing groups adjacent ordinary input only until a selection/focus change, structural command, paste, composition boundary or explicit history boundary; composition and paste each remain one group. ST-122 must supply grouping explicitly rather than assuming the current one-call/one-change facade already coalesces typing. Menus and previews create no history. Cancellation before admission preserves shared state; after admission, use author Undo rather than silently deleting a transaction.

| Command / input | Document and resulting selection | Undo / cancellation / concurrent contract |
| --- | --- | --- |
| Replace text / anchored range + scalar-safe text | Delete observed selected atoms, insert new atoms with appropriate typing marks; return caret after insertion. Plain title follows the same origin logic without rich nodes/marks | Typing group or one composition group; remote inserted atoms are not erased by stale offsets; re-resolve after offline rejoin |
| Insert block / stable collection boundary + allowed schema | Fresh scoped content labels/origins; insert at captured boundary; caret at first editable field or whole-node selection for non-text block | One; pre-commit cancellation no-op; remote boundary insertions use deterministic placement order |
| Split / merge / Enter / soft break | Reuse reviewed paragraph/list/toggle semantics; split retains suffix atoms and source metadata; soft break inserts newline, merge only compatible adjacent fields | One; resolve returned caret; do not flatten list/toggle/table metadata to force a merge; incompatible action is unchanged |
| Convert / origin + target block type/attributes | Shared schema conversion retains text origins, rich content and opaque metadata when representable; return anchored caret. Required structural role changes use existing conversion semantics | One; unavailable/lossy conversion rejects. Concurrent peer text follows retained origins; an invalid combined structure enters retained recovery |
| Format / anchored range + mark or remove | Set/remove supported mark on observed atoms; selection remains anchored. At caret, adjust local pending typing style only until inserted text makes it shared | One for an actual range mutation; no range means no history. Concurrent different marks compose; competing same-mark writes use shared deterministic ordering |
| List structure / selected compatible nodes + style | Preserve list/item origins, nested item content and checklist state; use schema conversion and list-only hierarchy commands. No arbitrary block indent/outdent | One per deliberate command; invalid cross-kind conversion rejects; peer item edits survive structural changes and Undo |
| Toggle disclosure / toggle origin | Opening/closing is personal presentation; changing summary/children uses ordinary shared text/structure commands | Disclosure no history/network edit; content edits grouped normally. Do not hide content from copy or logical assistive order because the local toggle is closed |
| Move / ordered whole nodes + compatible destination/boundary | Origins and descendant text/metadata remain unchanged; node selection/caret follows move. No partial-text drag represented as whole-node move | One; preview cancellation no-op; ancestry/cycles and indirect nested layouts reject; conflicting peer moves use reviewed placement ordering or retained structural recovery |
| Duplicate / ordered whole nodes + boundary | Deep-copy visible source content at admission; fresh schema identities only; references and opaque consumer metadata copied verbatim. Select duplicate nodes | One; later edits to original do not mutate the copy; Undo removes this author's copies, preserving peer edits to the original |
| Delete / mixed selection | Remove observed selected text atoms and explicitly selected whole subtrees; preserve independent text outside them. Return boundary caret/fallback | One; cancel confirmation no-op; if the combined projected history is invalid, retain recovery. No empty-document substitution |
| Link / anchored text + validated URL | Shared link mark or explicit labeled text insertion; selected range/caret remains resolved. Use inert validated URL metadata; opening/resolution belongs to host | One; cancelling URL editor no-op; unsafe or stale-target submission unchanged. Never fetch a URL during engine admission |
| Copy / mixed selection | Ordered rich fragment and explicit plain fallback; no document mutation. Hidden toggle descendants and both column containers retain logical order | No history; source changes after copy do not alter captured payload; no asset download/secret resolution |
| Paste / captured selection + inert normalized fragments + policy | Prefer versioned internal rich payload; freshen only schema identities. Plain multiline retains empty/trailing lines. External normalization is explicit, never used to strip accepted session content | One including replacement; cancellation/no provider result unchanged. Rejoin resolves captured anchors; unadmittable data remains available for retry/explicit fallback |
| Cut / captured selection | Copy successfully first, then delete the validated selected atoms/subtrees; preserve unrelated content | One deletion group; clipboard write failure prevents deletion; delayed provider rechecks captured origin |
| Undo / Redo / local author history | Toggle this author's admitted action/group, recompute current projection; preserve peer changes in surviving origins. Restore selection using group anchors, not old numeric offsets | No peer history toggles; newer local edit clears local Redo. Invalid projection retains full recovery and exposes explicit repair; archived epoch history cannot be replayed |
| Edit title / document origin + plain range | Concurrent plain title independent of body; no inferred heading deletion; explicit text selection/focus | Same typing/composition grouping as body; peer title insertions survive author Undo, offline rejoin and reopen |
| Set appearance / explicit individual preset field | Shared font family/size/page width only; preserve other fields. Current text selection and focus remain anchored | One field action; separate-register concurrent writes compose. Focus mode, outline visibility, zoom and stacking remain personal |
| Semantic color / range or block + palette role | Set/remove versioned semantic ink/fill marks or block defaults; appearance resolves named role into light/dark pair. Mixed selections show a mixed marker; reset removes the override and inherits the default | One; check supported role and contrast mapping; selected-state check/label supplement color. Preserve old opaque metadata, no automatic custom-color rewrite |
| Resolve async attachment/preview / captured origin + result | Host performs upload/preview work only within separately authorized boundaries. Successful engine admission changes only the still-live intended block's validated metadata | One completion mutation distinct from initial insertion; cancelling before completion preserves pending/error state as specified by the host; late completion cannot recreate deleted content |

Native title, formatting, list/toggle, file and URL-preview capabilities remain the agreed scope. The table does not authorize uploading, publication, credentials, new network services or extra block features. Existing clipboard rules distinguish permitted inert metadata from asset fetching; activation and autosave are host-owned durable transactions.

## Column creation, movement, removal and resize

**Create:** input is a valid block-collection boundary or contiguous sibling block selection plus the default split. Allocate one layout and exactly two column origins. Selected blocks move, with original origins, into the first container in original order; the second starts empty. Creating at a boundary creates two empty containers and an editable insertion position; no persisted fake paragraphs. Reject selections containing a layout or any layout descendant through toggles/lists, and destinations below an existing layout. One atomic transaction selects the layout or restores the original text caret inside its first column. Explicit cancellation leaves all content and IDs unchanged. Concurrent unobserved insertions stay at their own captured parent boundary unless their shared placement deliberately follows a moved node; the engine's reviewed placement semantics decide order, not viewport position.

**Move within/between/out of columns:** use the normal whole-node move with compatible block collections and stable container origins. Preserve original text/caret and node selection. Reject extra/nested columns through every descendant path. Sibling insertion, peer editing and author Undo resolve on the original origins; no whole-array write or copy/delete approximation. A peer move that would create an invalid combined structure cannot be silently dropped: retain the union and explicit repair under the common recovery boundary.

**Remove:** flatten every first-container child, then every second-container child at the former layout boundary in its parent collection, keeping existing origins/IDs/metadata. Retain routing from the removed column origins so concurrent/offline child insertions and text edits do not disappear into a tombstoned owner. This is a new compound structural semantic in ST-122, not today's generic subtree `delete`. A peer's explicit independent move remains effective under placement precedence. Preserve a text caret inside any surviving child; selection of the wrapper resolves to the flattened children/boundary. One transaction and one Undo. Undo reconstructs the same layout/container identities and split with peer edits preserved; Redo flattens the current logical content again. Concurrent removals converge to one flattening, without duplicates. If an accepted union cannot satisfy identity/ancestry invariants, retain recovery rather than orphan or relabel children.

**Undo creation:** deactivate only this author's layout action. Restore original selected nodes to their prior origin-aware placement. Peer children inserted into newly created containers must remain reachable at the former layout boundary in first/second order; do not discard their writes when layout/container birth becomes inactive. Explicit peer moves continue to follow their own placement. This requires retained structural routes for inactive ownership, analogous in intent to existing retained text origins but not claimed implemented.

**Resize:** input is a live layout origin plus integer split in 1000–9000. Pointer/touch drag records the shared starting value and uses local pixel previews; release admits one final split command. Cancel/ Escape removes the preview and reveals the latest accepted peer value, not a stale captured value. Keyboard/assistive adjustment uses a labeled adjustable control and deliberate grouped increments; Enter/release/focus completion commits one group, Escape cancels the active preview. Reduced hosts preserve split without offering resize. Responsive clamping/stacking never writes it. A peer update does not fight a local preview; after commit the shared winner is deterministic `ChangeID` order (Lamport counter then UTF-8 actor). Undo deactivates this author's resize and reveals the remaining peer winner or baseline, never restores an obsolete scalar over a peer edit. Offline rejoin uses the same rule.

Copying a whole layout retains two logical containers in the internal protocol-7 payload; pasting at a non-nested block boundary allocates fresh layout/container/content origins. Pasting into an existing layout cannot create a nested layout: reject the rich operation unchanged and offer an explicit **flattened copy** fallback that preserves every child's content in first/second order with fresh identities. Plain text export serializes first then second. Clipboard fallback is deliberate external import; it cannot be used to silently downgrade an accepted modern document or protocol packet.
