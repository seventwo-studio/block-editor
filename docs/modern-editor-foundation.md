# Modern shared foundation: snapshots, origins and sessions

Initial implementation for [ST-122](https://linear.app/seventwo/issue/ST-122), from the [ST-120 command contract](modern-editor-command-contract.md) and independent [ST-140 fixture contract](acceptance/modern-editor/README.md). This implements immutable snapshot admission/serialization, shared projection origins and an explicit protocol-7 session for text, appearance and author history. The checked bridge exposes the implemented command subset, including retained code/list shape conversion and soft breaks. Remaining list structure, semantic defaults, full focus/selection outcomes, clipboard, async completion, migration activation and typed host/JNI/WASM facade acceptance remain unfinished ST-122 work.

`ModernDocument(json:)` admits the exact format-1 envelope: document identity, plain single-line title, persisted appearance and ordered blocks. Unknown admitted envelope/appearance/block/inline fields survive canonical serialization. New documents explicitly receive an empty title and sans/default/readable appearance; received documents missing required fields reject instead of silently becoming a new document. Personal outline/focus and viewport stacking are not shared metadata.

The modern validation policy adds named semantic ink/fill roles and exactly two column containers with unique sibling identities and integral split basis points from 1000 through 9000. Descendant layouts reject even through toggle children; independent layouts at valid boundaries remain possible. Child labels remain scoped to their containers, preserving existing identity rules. Existing known block/inline validation is reused, including literal code, references, nested lists, tables and media metadata. Unknown blocks remain preserved without becoming authorable.

Raw JSON admission rejects duplicate object keys, including escaped spellings, before Foundation can collapse them. Numeric metadata rejects when a Double/canonical-JSON round trip would silently round the original decimal value. Callers retain the original bytes for archive/export/retry; this type performs no storage or activation transaction. Use the explicit raw JSON initializer at this boundary rather than introducing an unchecked decoder path. Structured fields retain their already represented JSONValue values. The existing 32 MB, 10,000-root and per-block nesting bounds are retained.

The shared structural projection now has an explicit `.document(documentID:)` origin for metadata and title atoms. It has no body placement, so a consumer block with the same string ID stays distinct. Modern column containers are typed collection owners; child identities include the layout and column path, and logical order remains first column then second. The internal `ModernProjectionSeed` reuses existing scalar atom allocation and run preservation instead of creating a separate title engine. All 55 accepted snapshots retain exact admitted fields through shared projection. A primitive replay check verifies peer title insertion through author deactivation and reactivation, with body and appearance preserved; this earlier primitive check does not establish admitted protocol-7 commands or session Undo. The session layer below has its own behavior verification.

The new public `NodeID` enum case requires downstream exhaustive Swift switches to handle the document origin. Legacy authoring/admission and clipboard paths reject it; protocol 3–6 writing and protocol 2 structural receive checks verify rejected proposals do not change saved state or receipts. Consumers must use an explicitly modern session.

Legacy `Document`, protocols 3–6, bridges and existing host behavior keep their existing admission policy. Their create/restore paths still reject protocol 7. New createModern/restoreModern endpoints explicitly admit modern sessions. Legacy opaque fields called `columns` or `semanticColor` are not reinterpreted as modern schema. Archive-based cutover and the remaining command/host matrix still require shared implementation and acceptance.

All 55 independently committed accepted ST-140 snapshots pass admission, semantic field preservation and canonical round trip, including the 5,001-block fixture. Focused tests cover malformed titles/presets/palette roles/layouts/splits, scoped identities, forbidden nesting, key/numeric preservation, limits and legacy rejection. The [implementation receipt](evidence/modern-document-foundation-2026-10-05/receipt.json) qualifies the broad regression run and final targeted checks by their source hashes. These are runtime snapshot checks; the command/concurrency/Undo and host acceptance scenarios remain pending in the existing matrix.

The [shared-origins receipt](evidence/modern-shared-origins-2026-10-05/receipt.json) records a full passing Swift regression over the new origins and shared helper extraction: 375 checks (291 core, 76 Apple adapters, 8 local-demo), including 18 modern snapshot/projection checks. Source/test hashes, unchanged independent fixture hashes and the original log identify this increment.

`ModernSession` admits an immutable modern baseline and uses protocol-7 batches/receipts, causal frontiers and atom references. Title and known body fields share scalar replay; title/literal fields reject rich atoms and title line breaks. Appearance presets are independent per-field registers, so a concurrent width edit survives font-size Undo. Operations remain validated when deactivated. Captured text ranges include their causal context, preserving direction and selecting only the captured atoms; later peer insertions are retained during replace/format. New source and independent title/appearance fixtures verify peer exchange, author Undo/Redo, saved history and new-author reopen.

Typing groups are explicit local history tokens. Hosts end them at selection/focus, paste, composition and command boundaries. One grouped Undo deactivates that author's transactions atomically while preserving peer atoms. Accepted history, held remote packets and pending recovery have separate budgets/exports; missing causal packets and schema-invalid unions leave accepted state/receipts unchanged. Held packets restore/retry through an explicit API, and release is idempotent. Repair can deactivate/reactivate only an accepted local author's history; peer history is retained. Local allowed-command policy restricts authoring without rejecting or stripping peer content.

The shared JSON bridge now exposes createModern, restoreModern, modernDocument, modernCommand, modernCapabilities and modern save/sync/position/composition/hold/recovery operations. Creation explicitly selects collaborationVersion 7. Checked command requests carry documentID/epoch, command, captured target and arguments; results distinguish applied/noop/unavailable/recoveryRequired and return the admitted transaction and anchored selection/focus when implemented. Current advertised commands are replaceText, replaceTitle, setAppearance, format, insertBlock, move, delete, createColumns, removeColumns, resizeColumns, convertBlock, softBreak, splitBlock, mergeBlocks, undo and redo. Raw modern requests retain duplicate-key/numeric inspection before dispatch; unknown command arguments reject. Legacy commands cannot mutate a modern handle. Schema-changing conversion and unsupported clipboard commands stay unavailable, and cutoverToModern is explicitly unimplemented. The existing C ABI routes these endpoints; typed Kotlin/TypeScript integration and executed Android/WASM parity remain pending.

## Structural session increment

ModernSession now authors insertBlock, move and delete in the same protocol-7 history as body/title text and appearance. Retained births seed the existing scalar projection, including nested toggle/list/table fields; creation Undo hides the author's initial text while retaining active peer edits. Moves between root and existing column children preserve origins and anchored positions. Deletion records observed subtree origins; stale local text targets reject instead of selecting a later block with the same display label. Generic commands cannot create column containers, mutate document metadata, create nested layouts or expose general block indentation. Column creation/removal/resize use the explicit compound operations described below.

Admission checks structural identities, placement boundaries, causal observation and element-index uniqueness across text/structure operations. Incremental inserted-field packets received before their birth retain a separate recovery proposal without advancing accepted receipts; delivery of the missing birth completes replay. Conflicting scoped labels retain structural recovery and permit author-only repair. Local policy restricts structural authoring without discarding peer content.

The JSON bridge admits these structural packets and exposes checked insertBlock, move and delete commands. Captured boundaries retain their original placement after peer movement/deletion; captured node selections retain origin IDs and order while rechecking current liveness/overlap. Multi-node moves and mixed text/subtree deletions are atomic author transactions. Mixed deletion removes captured text atoms, preserving later peer text outside explicitly selected subtrees. Result planning completes before accepted state/history publication, so a failed result cannot leave a partial edit. Canonical focusIntent/selectionIntent distinguish text positions, whole nodes and an empty-body insertion boundary; existing text focus/selection fields remain compatibility aliases. Deletion chooses following text, preceding text, then document/title, without persisting a placeholder. The [command API](modern-editor-command-api.md) documents the implemented targets and result boundary. Versioned clipboard, conversion/split/merge/list structure, semantic defaults, async completion, archive-based cutover, typed Kotlin/TypeScript facades and executed Android/WASM/full host acceptance remain required before ST-122 closes. No complete ST-140 scenario or host row is promoted by this increment.

The [structural receipt](evidence/modern-structure-2026-10-05/receipt.json) records the full regression and final targeted checks separately, plus native C ABI structural receive/edit/Undo/Redo/reopen checks. Historical receipts continue to qualify their own source revisions.

The [checked structural receipt](evidence/modern-command-targets-2026-10-05/receipt.json) qualifies that increment's regression, targeted checks and 56 compiled native ABI responses against six independent fixtures. The nested whole-node move matches the independently committed expected snapshot and restores the exact baseline through one author Undo. This covers the implemented shared-core/bridge behavior; native rendered focus, typing/composition, full scenario/host matrix and the remaining command set require their own acceptance evidence.

## Compound shared columns

createColumns, removeColumns and resizeColumns now use the same protocol-7 history as text and generic structure. Creation groups current contiguous siblings into the first of exactly two empty column owners at split 5000, preserving every selected origin and optional caret. An empty layout has no placeholder paragraph. Creation at an existing block-child boundary is allowed outside any layout; direct and indirect nesting reject. Removal flattens current children in first/second logical order and retains the old owners for late offline text and child packets. Explicit independent peer moves keep their placement. Concurrent removals render each origin once. Creation Undo restores original selected placements and routes peer children after that selection; saved history restores the same behavior.

Derived columnRoute anchors include a route slot so subsequent root insertions anchored after flattened content remain reachable after removal Undo or creation Redo. Raw owner placements stay retained for causal admission; the derived view alone flattens them. Invalid unions retain accepted state/receipts and an author-repairable recovery proposal. Split registers use ChangeID counter/actor ordering; author Undo reveals the remaining peer winner, and unchanged final splits add no transaction. Preview/cancel and physical splitter interactions remain host acceptance work.

Modern edited run rendering matches the independent unmarked column snapshots while retaining untouched JSON and explicit empty-mark birth representation. The new public NodePlacementID columnRoute case requires downstream exhaustive switches. Protocols 2–6 reject its namespace without changing save/receipts.

The adapter preserves each admitted change ID and causal frontier, supplies modern grouped activity explicitly and keeps the modern empty-mark representation policy. It reuses the retained-origin, alias and ordered-cut machinery without invoking legacy packet admission or changing legacy defaults. A shared pure metadata conversion helper keeps legacy validation behavior and enforces modern attribute values separately.

convertBlock retains the same field and atom origins for paragraph/heading/quote/callout changes and list style changes. A nested list-item caret targets its containing list's style. Rich runs, reference atoms, checklist state, descendants and opaque consumer fields survive. Conflicting opaque attributes reject rather than being overwritten. Concurrent heading values converge by author/change ordering; author Undo reveals the peer value. A captured nonempty field-end caret now anchors after its observed final atom, so a peer suffix does not shift it past that suffix. Saved history retains the same caret and Undo/Redo behavior.

## Retained field cuts and joins

splitBlock and mergeBlocks now reuse the existing retained writing projection and shared split-operation builder. Inline paragraph/heading/quote/callout cuts retain source metadata and place suffix atoms in a new paragraph. Nonempty list-item cuts retain original children/metadata and create a sibling item, resetting a new checklist item's checked state. Current typed source containment controls the new sibling placement; this does not expose general block indentation or collection writes. Concurrent cuts partition retained atoms in text order. Capture proof can rebase through an already observed peer cut, and deactivation cannot hide malformed cut proofs.

Compatible adjacent paragraphs join without copying atoms. The right paragraph must have no metadata/collections that joining would discard. Source caret anchors, captured edits and later peer text follow the joined field. A shared position resolver handles atom destinations, tombstones and retained field heads; legacy callers preserve their existing scope and retired-birth admission. Modern empty split-head positions return through the exact birth boundary on Undo, including chains of retired births, and explicit unrelated deletion still rejects. New tail input uses the original retained anchor even when its atom originated in another field. Local command results never move peer focus.

## Retained schema conversion and sole empty-item Enter

Code/inline/list shape conversion now uses the existing pure planner and materializer after modern causal admission. Immutable text field births stay separate from the current visible node shape; aliases route original atoms, field handles and captured carets through conversion, author Undo/Redo and reopen. New text uses the current destination birth. Formatting checks the field in the author's causal view, allowing code-born atoms to become rich text after paragraph conversion while rejecting formatting in a current code field. Captured anchor families use the original observed history; a later join cannot justify an unrelated earlier capture. A compound packet that creates a node and its text uses its validated same-edit birth, so a subsequent alias does not retroactively invalidate that packet.

List creation introduces one retained item, with unchecked state for todo style. Sole-item collapse keeps the original list owner, retains checked/opaque item metadata and child origins, and rejects conflicting metadata. Multi-item collapse and rich/reference/opaque-inline conversion to code reject unchanged. Code language and consumer fields remain opaque through subsequent conversion. A peer's split after list creation remains a visible paragraph if the creator undoes the list conversion. Historical typed collection shape is shared with legacy replay; temporary validation never overwrites the visible owner.

A sole empty root list-item Enter converts its existing owner to a paragraph in one author step, preserving children and later peer text. Nested/multi-item empty Enter, general list structure and subsequent structural commands on exposed retired list roles remain required. This increment preserves the full ST-122 scope and the native acceptance gates.

The existing pure planner and role materializers are shared after separate modern admission. Captured empty intent with newly observed peer text uses an ordinary retained item cut; noncollapsed captures are not reinterpreted as empty Enter.

Modern commands pin the exposed paragraph roles they use, including predecessor role anchors, against immutable birth, original exposure, retirement and author-cohort proofs.
