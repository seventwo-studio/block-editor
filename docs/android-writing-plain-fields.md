# Android code and math fields

The explicit protocol4/5/6 `WritingBlockEditor` renders shared code and math fields as strings owned by their opaque node identity. Native edits use existing shared replace-text and soft-break commands. Enter does not split a code/math block. The same native lease, final composition correction, held-peer drain, anchored caret, failed-draft retention, host recovery and author Undo/reopen contract applies. The older root rich-only paragraph surface stays rich-only.

Plain fields offer copy/cut and literal plain Paste. Native multiline text becomes one inline text fragment with normalized line endings. Typed rich marks, references, opaque inline metadata and structural blocks reject before native finalization; they are never flattened silently into code. Core strict paste validation still runs at admission. Format, paragraph merge/conversion and Markdown structural shortcuts remain unavailable. Explicit Markdown buttons are hidden on these plain fields, and retained action callbacks reject them before reading the clipboard. No epoch is upgraded and no platform document array is rewritten.

Empty code is valid and editable. Required code/expression fields cannot be absent in an accepted schema; the renderer keeps an unavailable field inert rather than creating one, and actual session admission rejects malformed missing fields. Required math expressions retain failed empty drafts with accepted snapshots and held packets until the user corrects or the host persists them. Closing with a failed host retention callback leaves the original owner and drafts available.

Checklist checkboxes receive their visible item text as an accessibility description, with “Checklist item” for empty content. Existing checked and disabled semantics are retained. A semantics assertion does not establish actual TalkBack acceptance.

Five mandatory typed JNI owner methods cover4/5/6 and both code/math: Unicode composition and peer delivery before Enter, caret and rich-sibling preservation, one-author Undo/Redo/reopen, plain multiline paste and rich/structural rejection without finalization, stale/read-only/moved/closed leases, failed math draft/export retention, and empty code versus missing-field rejection. Existing collection Compose witnesses additionally assert a stable meaningful checkbox description before/after toggle. Actual current JNI/Compose, installed keyboard, device and accessibility acceptance remain required.
