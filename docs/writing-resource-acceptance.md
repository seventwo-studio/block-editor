# Packaged writing resource acceptance

`benchmarks/resources-writing.json` specifies the production32,000,000-byte document limit,64,000,000-byte retained capacity (canonical batch plus1,024 bytes and the sorted authored-edit ID array), and10,000 ROOT blocks. Protocols4,5 and6 are explicit; these checks require the integrated protocol6 engine. Payloads and roots are generated from the recipe rather than stored as giant fixture files. Literal rich Unicode/reference/opaque metadata and repair/history expectations follow `WritingByteRootBoundaryTests`.

Five cases per protocol exercise exact/one-over document unions, exact/one-over retained packets with caller-owned rejected archive and explicit epoch cutover, and exact/one-over root unions with a nested peer child. Invalid unions preserve accepted save/receipts, separate recovery survives reopen, wrong-author repair remains atomic, valid author repair preserves peers, and invalid ordinary Redo is retained through another restart/repair. No request or command ABI changes. No limit is reduced.

Native uses a fresh bridge process per case; WASM uses a fresh instance/page; JNI force-stops only the disposable testhost on the wiped job-owned AVD before each case, then records the actual Android process PID; the runner and parity verifier require a positive PID distinct from the previous case. PID is runtime-only provenance and is excluded from shared result parity. The per-case900-second watchdog accommodates real production payload work; instrumentation, raw fixture, IME/UI and performance gates retain their own watchdogs. Resource failures remain failures. Reports begin incomplete and persist on failure.

These are **compact resource proofs**, separate from the unchanged raw fixture transcripts. Canonical save/proposal/rejected-packet byte counts and SHA256 fingerprints allow cross-runtime comparison without retaining hundreds of megabytes of raw duplicate responses. Kotlin fingerprints stream canonical JSON to avoid extra large measurement buffers; actual JNI request/response serialization remains exercised. Artifact-bound parity requires all105 proofs (15 cases in seven runtimes) from the same clean source/tree and recipe hash, tied to the debug native bridge, actual WASM or selected APK JNI/Swift/C++ libraries. Actual host input/recovery presentation and release memory budgets remain separate acceptance.
