# Protocol 6 retained endpoint splice candidate

This source-only candidate introduces an explicit epoch. No existing session, archive or host upgrades automatically. Version 4 and 5 peers reject version 6 batches before admission; generic unknown-version checks advance to 7. The older version 3/4/5 wire semantics and literal fixtures are preserved. Existing sessions retain their explicit epoch. The additive Apple clipboard candidate accepts explicit versions 4, 5 and 6; current installed-host adoption is still unverified.

`rangeSpliceBoundary` orders one complete imported chain ending in an existing paragraph owner. The descriptor records the retained source and endpoint placement proofs, the source cut edge, an outer neighbor, all imported members, and the exact same-edit endpoint move. Every earlier member is a same-edit fresh birth; the last member is the existing endpoint. Import data is inert and validated by host block/mark/asset policy before authoring.

The planner deletes observed source-suffix and endpoint-prefix atoms, deletes only observed intermediate subtrees, inserts complete fresh middle nodes and boundary inline atoms, and moves the endpoint in the same author edit. Original root and endpoint metadata namespaces remain separate. Their opaque NodeIDs, rich atoms, references and endpoint metadata survive. If the source has no prefix or explicit leading inline field, its selected whole root retires; the existing endpoint remains the suffix owner, avoiding an incidental empty first block. An unseen descendant can still retain the selected source/intermediate container through the existing structural reconciliation rules.

Admission requires known source and endpoint placement proofs in one retained collection. These prove origin and collection; they do not authenticate physical user selection or require an RGA ancestor-after relation. The public planner normalizes current visible range order. As with existing low-level move/delete operations, callers may author any otherwise valid explicit edit. Recorded edit placements, endpoint atoms and source rank pins must belong to the author's observed cohort. Fresh leading inline atoms in the current edit remain valid. Initial placements for nested descendants of an observed earlier inserted node are valid; root insertions use their edit placements. Role placements require the validated current role prefix and observed retirement/exposure proofs. Only the exact declared endpoint move participates in cut-rank group ordering; later independent moves stay authoritative. Duplicate group claims inside a packet are malformed even when inactive. A later range that causally observes an earlier claim to the same endpoint supersedes only that endpoint claim. Earlier fresh members and text history remain retained, including when the later range begins at a different source. Undo restores the prior claim. Physical ordering uses each remaining group’s unique last member. Independent later moves are excluded from the former birth group’s container claims. Concurrent active authors claiming the same retained endpoint or overlapping group return schema recovery; disabling either competing author edit is the supported repair route, rather than choosing a dictionary winner.

Same-field semantics inherit protocol 5. Protocol 6 also supports a single inline replacement across metadata-bearing endpoints and ranges spanning different nested collections. The shared selection traversal normalizes the visible endpoints and deletes only observed selected atoms and whole intermediate descendants. Boundary owners retain their original opaque identities, metadata and child collections. When a lossless join cannot preserve both namespaces, both owners remain separate in their original collections; no hidden metadata archive is created. Unseen peer atoms and descendants remain live, and one author edit owns the replacement and returned caret.

`importBoundary` records an observed source edge, current source placement, explicit compatible target collection, outer neighbor and complete same-edit fresh member chain. Whole imports preserve rich content, references and unknown attributes while receiving fresh schema IDs. Only explicit leading/trailing inline parts are absorbed into the corresponding boundary fields. The target is either the source's parent collection or a compatible source-owned collection when the ending field lies below that source. Whole-node kind mismatches reject before mutation; external import normalization can provide a permitted paragraph fallback without changing the strict paste API or downloading assets.

Physical import-chain ordering is partitioned by the descriptor's declared target collection, while text cut-rank arbitration stays shared. This allows a list item's child imports to coexist with a concurrent Enter tail in its parent's item collection. Independent later member moves remain authoritative. Observed-cohort, retained-role, same-edit identity and host-policy admission rules remain explicit to version 6; protocol 3–5 wire behavior is unchanged.

The isolated hierarchy checkpoint passed 111 native focused cases. The new `paste6Commands` corpus and actual typed Kotlin/WASM tests retain independently authored document, caret, origin, composition and author-history oracles. Their combined execution, installed JNI/WASM, replay-cost and native clipboard/input acceptance remain pending. These source and component checks do not establish platform acceptance.
