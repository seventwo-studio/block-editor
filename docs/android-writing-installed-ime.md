# Installed Android shared-writing input candidate

The additive `WritingBuiltinImeTest` executes two explicitly enabled tests on the already installed API26 x86_64 LatinIME. The job-owned `--system-ime` row runs the original legacy keyboard/reopen/plain-paste/asset campaign first, then the new shared-writing runner. Both new methods must execute and pass; assumptions or skipped instrumentation fail the runner. Existing keyboard-key discovery retains its eight-second limit, system-app and English-subtype checks, foreground assertion and actual observed touchscreen bounds. No replacement keyboard, input interceptor, synthetic composition setter or semantic toolbar action is used.

Each method first proves marked composition in a vanilla native field using physical c/a/t/Space keys. It then types the same word into `WritingParagraphEditorState` with an explicit protocol4 `WritingSession`, retains a remote R packet while native composition remains active, and physically taps visible Enter or Soft break without first committing with Space. The accepted save and exact receipt remain unchanged while the packet is held. The command must finalize the original native lease, commit the local draft, drain the remote packet, execute one shared structural edit, and restore the returned native caret/focus. Original italic Unicode, reference payload and opaque host metadata stay exact in a separate rich paragraph.

Physical Undo removes only Enter/Soft break while retaining the committed native word and remote R. Redo restores the exact document. Further physical author Undo removes local typing while preserving the peer-only document; two Redos restore the accepted document. A typed save/restore checks offline author history separately; this is not an installed process-restart claim. All observations use actual rendered field selection, focus and toolbar enabled state.

The new runner records supplied/installed APK equality, packaged JNI hashes, exact source/dirty boundary, test hashes, target SDK, keyboard package, device fingerprint, screenshot/input-method dumps, observed key touches and callback/accepted/deferred/draft state. Failed native finalization or remote delivery retains diagnostic accepted saves, deferred packets and draft/recovery exports; conditional diagnostics do not establish physical failed-repair acceptance. Tests have no capability to drop a packet or reset an input to pass.

This is an uncompiled source candidate. The eight existing controller tests, four owned-connection component tests, every legacy installed-IME test and their mandatory gates remain intact. Installed API26 execution, current-runtime/device rows, actual native failed-repair paths, broader writing/structure commands, assets, structured paste, TalkBack and complete platform acceptance remain open until their own current-build evidence passes.
