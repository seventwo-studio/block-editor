# Native writing clipboard

The Apple writing model accepts explicitly selected protocols4,5 and6 without upgrading a session or epoch. New retained endpoint semantics require protocol6. Native macOS/iOS/visionOS paste finalizes composition and drains held peer changes before deriving the selected range and invoking one shared paste command. Existing protocol4 uses its shared inline paste, including literal plain-text line breaks; whole-block and broader selection paste require explicit protocol5 or6. Single-line plain text stays inline on all three protocols. Internal copy stores an inert typed clipboard and a plain-text companion; reference metadata and supported marks use the shared representation.

External text and typed clipboard input pass through shared import normalization and the host's `pastePolicy`/`allowedBlockTypes`. Paragraph fallback is suggested by normalization, but the live host policy is never expanded automatically. Image/embed metadata stays denied unless the host explicitly permits it; no asset download occurs. Malformed typed data, unsafe URLs and disallowed content cannot trigger a separate native document mutation. Failed commands remain visible through the model error and accepted content stays selectable.

“Paste Markdown” is an explicit native menu action on macOS/iOS/visionOS. It deliberately reads the actual plain-text representation/companion even if an internal typed DTO is also present. Ordinary Paste still prefers the typed DTO and treats plain text literally; standard Paste/Paste and Match Style and keyboard shortcuts are unchanged. Markdown delegates the shared document dialect (headings, lists/todo, quote/callout, fenced code, tables, math, divider and image metadata); inline emphasis/link syntax has the same existing literal-text behavior as that parser. It normalizes CR/LF and bounds input to 1M UTF16 units/10k lines before parsing. v4 accepts only a single parsed paragraph through existing inline paste; structural Markdown rejects without upgrading an epoch. v5/v6 use shared selection paste, host restrictions and import normalization. Asset metadata cannot initiate a download.

This adapter handles internal structured clipboard, the system plain-text representation and explicit Markdown. Dedicated HTML/RTF adapters, cross-field UI selection, installed system IME, clipboard consent, asset interaction and VoiceOver acceptance remain separate checks. Component callbacks are not device acceptance. watchOS/tvOS retain their agreed native reading/text/checklist/ordering surfaces.

The merged browser HTML adapter in `src/clipboard.ts` requires an inert DOM template and produces schema data for shared import/paste. Native code does not call Foundation HTML attributed-string import or create a remote WebView document. A native raw-HTML parser and RTF sanitization remain open. A host can supply already-sanitized typed clipboard data through the existing explicit contract; this does not establish native HTML acceptance.
