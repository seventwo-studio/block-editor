# Native writing clipboard

The Apple writing model accepts explicitly selected protocols4,5 and6 without upgrading a session or epoch. New retained endpoint semantics require protocol6. Native macOS/iOS/visionOS paste finalizes composition and drains held peer changes before deriving the selected range and invoking one shared paste command. Existing protocol4 uses its shared inline paste, including literal plain-text line breaks; whole-block and broader selection paste require explicit protocol5 or6. Single-line plain text stays inline on all three protocols. Internal copy stores an inert typed clipboard and a plain-text companion; reference metadata and supported marks use the shared representation.

External text and typed clipboard input pass through shared import normalization and the host's `pastePolicy`/`allowedBlockTypes`. Paragraph fallback is suggested by normalization, but the live host policy is never expanded automatically. Image/embed metadata stays denied unless the host explicitly permits it; no asset download occurs. Malformed typed data, unsafe URLs and disallowed content cannot trigger a separate native document mutation. Failed commands remain visible through the model error and accepted content stays selectable.

This adapter handles internal structured clipboard and the system plain-text representation. Dedicated HTML/RTF adapters, cross-field UI selection, installed system IME, clipboard consent, asset interaction and VoiceOver acceptance remain separate checks. Component callbacks are not device acceptance. watchOS/tvOS retain their agreed native reading/text/checklist/ordering surfaces.
