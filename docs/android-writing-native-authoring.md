# Android shared writing authoring increment

`WritingParagraphEditor` remains an additive root rich-inline surface. It accepts an explicitly selected writing epoch 4, 5 or 6 and edits paragraph, heading, quote and callout content using opaque origin controllers. Existing legacy `BlockEditor` consumers retain their API. The surface neither upgrades an epoch nor replaces a document array.

Enter, soft break, merge, contextual formatting, inline block conversion, copy, cut and paste use the current owner lease. Each command revokes the native input connection, accepts only its immediately current final callback, commits the marked draft, drains held peer packets and derives the anchored selection before calling the shared engine. A retired, moved, read-only or disposed callback cannot author a command. Failed composition or peer recovery keeps its retained draft instead of attempting paste.

Typed copy writes inert shared clipboard JSON plus a plain text companion. Paste reads only `ClipData.Item.text`; URI and Intent coercion, asset downloads, HTML execution and remote fetches are excluded. A typed MIME payload first passes a nonrecursive, quoted-string-aware128-container envelope guard and the external text limit, then the JSON parser and shared normalization. The live `pastePolicy` and session host block restrictions remain authoritative; a suggested paragraph fallback never expands those restrictions. Plain CR/LF input normalizes line endings: epoch4 inserts inline literal breaks, while5/6 use the shared multiline clipboard factory. Epoch4 calls the existing `pasteInline`;5/6 call `pasteSelection`.

The rendered Copy/Cut/Paste and Bold/Italic/Heading/Paragraph controls and hardware shortcuts route through these same leases. The platform selection toolbar and installed keyboard clipboard controls still need their own acceptance; their default plain-text replacement does not establish structured paste acceptance. Rich origin and returned caret requests are applied before requesting focus on the fresh native field.

The new typed owner tests cover all three epochs with marked final correction, Unicode, atomic references, held peer edits, one paste/cut author Undo, reopen, host rejection and stale/read-only/closed callbacks. New Compose tests exercise the real controlled field, intercepted `InputConnection` and rendered paste/format/conversion actions. These source tests are not installed IME, physical ARM64, TalkBack or device acceptance, and require current execution.

ST-103 and ST-46 still require installed API26/current IME and focus conditions, physical architecture input, assets and accessibility; full slash/list/checklist/table/toggle controls, nested fields, dragging/nesting, keyboard navigation and cross-block UI selection also remain open. The existing shared Kotlin APIs provide those commands; this increment does not simulate their acceptance through the root inline surface.
