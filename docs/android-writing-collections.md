# Android shared Writing collection authoring

`WritingBlockEditor` is an additive Compose surface for an explicitly created Writing protocol 4, 5 or 6 session. Create `rememberWritingBlockEditorState(session, retainDrafts, reportError)` once per rendered surface and close the native surface before its session. `WritingParagraphEditor` and its original state constructor remain available with their root rich-inline scope.

The collection surface renders paragraph, heading, quote and callout content, toggle summaries and children, ordered/unordered/checklist items and their nested items, table rows/cells, and image captions. Enter dispatches to the shared paragraph split or list continuation/empty-item exit; summaries, cells and captions use a shared soft break. Indent/outdent, reorder, duplicate, delete, list style, checklist checked state, and fresh paragraph/list/toggle/row/cell insertion use shared commands. Existing formatting, copy/cut/paste, conversion and author Undo/Redo controls are reused.

Every author command finalizes the immediately current native input lease, commits its final marked text, drains held peer history, and then computes current opaque identity, collection order and anchored selection. A returned caret is adopted by the destination's fresh lease. A clean old split source refreshes its own accepted prefix without becoming a draft; its original retained selection remains available for destination handoff and author Undo. Marked, committing and failed drafts remain preserved. Disposed structural controls have their own rendering lease; read-only, closed, moved or replaced-origin callbacks cannot write through a retained label.

Paragraph and collection operations retain shared rich atoms, references and unknown metadata. Scalar checked-state authoring uses the shared scalar setter; protected identity, text and collection fields remain rejected. Paste uses the current host import policy and existing explicit epoch command support. Protocol 4 supports shared inline paste; protocols 5/6 use their supported selection paste. A rejected import or unsupported schema command does not become a platform array rewrite or an automatic epoch upgrade.

`renderAsset` receives a defensive copy of inert block metadata. The surface does not fetch URLs, download assets or choose host assets. Hosts own rendering and resource selection. Optional absent rich fields have no shared field birth; the surface keeps them inert rather than inventing an array, while newly inserted templates explicitly contain empty rich fields. Child fields retained as opaque paragraph metadata after a list collapse remain preserved; this does not make those unknown paragraph fields new authorable schema collections.

This increment includes seven typed JNI owner witnesses (each covering 4/5/6) and four rendered Compose/InputConnection witnesses with mandatory runner counts. Compilation, actual installed JNI/Compose execution and installed keyboard/accessibility acceptance are separate evidence. The tests cover composition and held peer delivery before a nested split, clean-source handoff followed by another command, checklist continuation/checking/indent/outdent, post-drain append, duplicate/delete and peer subtrees, independent summary/cell/caption fields, empty checklist exit with peer children, scalar rejection, absent-summary duplication without field invention, stale/reused/read-only leases, disposed controls after move-away/return, impossible actions that preserve marked drafts, inert asset copies and author Undo/reopen.

Remaining native acceptance includes installed keyboard and TalkBack testing, physical devices, drag/slash controls, multifield selection controls, plain code/math editing, host asset selection and any host-specific resource/accessibility policy. This surface does not claim that broader acceptance from source or compilation alone.
