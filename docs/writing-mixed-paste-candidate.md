# Shared mixed clipboard selection planner candidate

The additive `pasteSelection` command is a protocol5 authoring API with a separate explicit protocol6 retained-endpoint capability. The protocol5 path remains independently scoped. It emits only existing protocol5 operations; it does not change wire admission, replay, projection, old epoch behavior or old fixtures. Same-field pure inline and pure whole-node inputs delegate to the existing commands. Composition must commit before authoring. External normalization is an explicit shared `normalizeForImport` step; strict paste admission remains unchanged, and image/embed metadata requires explicit host policy. Paste never fetches assets.

The initial planner replaces one paragraph-field range. Every whole `.node` part remains complete and receives fresh schema identities, including schema descendants. Only explicit leading and trailing `.inline` parts merge with the destination boundary fields. Distinct interior inline parts become fresh paragraphs. Original prefix/suffix rich atoms and metadata survive; an observed prefix or explicitly leading inline field (including an empty one) uses the existing complete-group splice descriptor and a fresh continuation, while offset0 without an inline prefix keeps the original suffix owner instead of introducing an empty prefix.

One allocator owns all authored text and structure element IDs, and one `perform` owns the whole edit. New leading atoms follow the observed prefix anchor, so a truly concurrent earlier split can move that prefix and its pasted continuation together. Explicit observed-prefix pins and suffix transfers reuse the delivered v5 arbitration. The returned caret follows the last imported trailing atom, or the original suffix boundary. Imported/continuation paragraph policy is checked only when a paragraph is actually authored; editing a retained paragraph is not a new authored type.

The isolated protocol5 checkpoint passed its focused native cases. Protocol6 hierarchical behavior has a separate 111-case focused checkpoint. The combined delivery source and new literal/typed corpus still require current execution. The tests contain independent Unicode, rich-reference, opaque metadata, duplicate/reopen/Undo and actor-order oracles; none establishes installed platform acceptance.

A same-collection paragraph range can replace its observed boundary spans and intermediate subtrees in one transaction when the ending paragraph has only id/type/content and no child collections. This matches the existing lossless merge policy: one inline part joins the suffix into the original prefix; mixed/whole parts join it into the authored continuation. Unseen intermediate descendants keep their container through delivered structural reconciliation, and unseen text following deleted source atoms travels with the continuation. Reverse selections normalize by current collection order.

Metadata-bearing cross-block endpoints reject atomically under protocol5; protocol6 records an explicit retained-endpoint move group or preserves separate owners across nested collections (see writing-protocol-v6-candidate.md). Their suffix owner is an existing metadata-bearing endpoint with foreign descendants, whereas delivered v5 group descriptors require all members to be same-edit births. A manual endpoint move bypasses retained cut-group ordering; composing separate deletion and paste violates one-author-Undo. A new explicitly versioned range-splice descriptor must prove the observed endpoint/span, retain its origin and metadata, and order the selected placement while preserving later foreign moves. Old protocol5 packet semantics must remain unchanged.

The current shared Markdown factory uses the existing documented limited dialect: block headings/lists/checklists/quotes/code/table/math/image imports are supported; inline formatting and arbitrary Markdown roundtrip fidelity are not implemented by that parser. This must be qualified and tested before native format adoption. The additive AppKit/UIKit clipboard candidate imports inert typed clipboard data or plain text, commits native composition and drains held peers before capturing the current shared range, then uses shared normalization and one paste command. Current installed input, HTML/RTF adapters and clipboard acceptance remain outstanding. No browser migration is included in this candidate.
